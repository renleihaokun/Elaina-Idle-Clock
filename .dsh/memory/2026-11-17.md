# 2026-11-17 凌晨自愈后不回全屏的修复（页内软自愈 + 全屏意图兜底）

## 背景
用户反馈：开着「每日 04:00 自愈刷新」，凌晨自愈结束后页面掉出全屏，
得进设置点「🖥️ 切换全屏模式」才回去。

## 根因（已核实）
- `scheduleAutoReload()` 到点直接 `location.reload()`。全屏是 document 的状态，不跨导航，
  刷新必然退出全屏。
- 新文档没有用户手势，`requestFullscreen()` 必然被拒（要求 transient user activation）。
- 规范层面：WHATWG 至今没有「刷新后自动恢复全屏」能力（whatwg/fullscreen#262 仍 open），
  Chromium 的 Automatic Fullscreen Content Setting 只给隔离 Web App（IWA），普通网页用不了。
- 结论：只要还刷新，就不可能零点击。修法只能是「别刷新」。

## 改动（全部已落地）
### script.js
- **页内软自愈** `runSelfHeal(trigger)`：不导航，回收重建
  1) `ElainaFX.reset()`（含 canvas backing store 释放）；
  2) 壁纸重新 preload → apply（解码成功才切，失败保留旧图）；
  3) 静态毛玻璃按新图重建；
  4) `Bemfa.reconnect()`；
  5) 重挂 04:00 定时器与壁纸轮换；
  6) `kickCompositor()` + `syncMaskState()`/`syncFxPaused()` 复原黑屏/暂停；
  7) 30s 后 `verifySelfHeal()` 只记录 + 补一次恢复（升级刷新仍归背景审计）。
- **04:00 定时器**：`location.reload()` → `runSelfHeal('daily')`；不再写 `elaina_last_reload`
  （那是 `safeReload` 的 10 分钟防抖键，写了会挡住真需要的刷新）。
- **背景审计**：连续 3 次丢失 → 先 `runSelfHeal('bg-lost')`；再来 3 次才 `safeReload`。
  `auditBackground()` 加 `state.selfHealing` 互斥。
- **全屏状态保持**（新小节，script.js ≈1395~1515）：
  `isFullscreen()` / `requestFullscreenSafe()` / `writeFsWanted()` /
  `onFullscreenChange()` / `armFullscreenRestore()` / `initFullscreenRestore()`。
  - 进入全屏 → `sessionStorage.elaina_fs_wanted = '1'`；
  - **退出全屏延迟 2s 再清标记**（刷新时 fullscreenchange/pagehide 先后顺序不确定，立即清会丢证据；
    页面卸载时定时器不执行，标记自然留存；手动退出 2s 后清掉，避免下次加载抢全屏）；
  - 加载后有标记 → 没激活过就 `armFullscreenRestore()`，在 pointerdown/touchend/mouseup/keydown
    （capture、passive）上挂一次性恢复，成功即摘监听，失败继续挂着；
  - `toggleFullScreen()` 改为走统一入口，主动退出时立刻清标记。
- `?selfheal=1` 测试钩子 + `window.elainaSelfHeal`（控制台可手动跑一次）。
- 设置项文案改为「每日 04:00 自愈（不刷新页面）」，id 与 `elaina_auto_reload` 键不变，默认仍关闭。

### effects.js
- 新增 `ElainaFX.reset()`：停链 → `clearCanvas()` → `cv.width/height = 0`（释放 backing store）
  → 清 oneshots/画质计时/baseline → `fitCanvas()` → `buildPreset()` → `restartLoop('self-heal')`。
  `restartLoop` 自带 paused/off 判断，夜间黑屏调用不会偷偷起循环。接口纯增量。

### bemfa.js
- 新增 `Bemfa.reconnect()`：`desired` 为真才重连，不动遮罩亮度、不改 desired。

### index.html / README.md
- 文案更新；本地资源版本号统一 `?v=20261117`（不升版本号手机会继续跑旧缓存）。

# 追加（同日晚）：壁纸按手机屏幕比例过滤

## 背景
用户反馈：随机图源会给出方图，和红米 8A（720×1520，19:9，比值 ≈2.11）的屏幕比例差太多，
全屏铺满时被裁得只剩中间一条。

## 根因（已核实）
- 图源随机接口 `GET https://elaina.haokun.me/` 是上游 `functions/index.js` 从 `imgs/manifest.json`
  等概率抽一张原图，**没有尺寸/比例参数**，服务端挑不了。
- `imgs/manifest.json` 只有文件名；带 `w/h` 的只有 `imgs/thumb/manifest.json`（103 张 640px 缩略图）。
- 旧 `pickNextThumb()` 只有 `w >= h` 一句，3 张 640×640 方图和一堆 1.0~1.5 的近方图都能进池。
- 展示是 `.bg-layer{object-fit:cover}`：19:9 屏上 16:9 图裁 15.8%、1.6 裁 23.4%、方图裁 **52.6%**。

## 改动
### script.js
- 新增 `deviceAspectRatio()`：`screen.width/height` 长短边归一（红米 8A 报 360×760 → 2.111），
  取不到退 `innerWidth/innerHeight`，再不行兜 2.0。
- 新增 `coverCropOf(imgRatio,target)`：`1 - min/max`，就是"铺满全屏要裁掉多少"。
- 新增 `buildThumbPool(images)`：按 crop 分级过滤，档位 0.20 → 0.35 → 0.50 → 0.65 → 0.80 → 0.95 → 1；
  池子 < `BG_ASPECT_MIN_POOL`(10) 或只剩当前这张就降一档，最后一档永远全量（不会空池黑屏）。
- `pickNextThumb()` 重写：走 `buildThumbPool`，池内还有别的图就一定换一张（修掉"随机 10 次还是自己"）。
- 新增 `readBgAspectPref()/bgAspectLimit()/initBgAspect()/applyBgAspect()`，
  localStorage `elaina_bg_aspect`，默认 `standard`；切档后当前图超标就 `scheduleBackgroundSwitch(1200)`。
- `preloadNextBackground()` 原图兜底：解码后算 crop，超标丢弃重试（`BG_ORIG_ASPECT_TRIES=3`），
  全超标就用最后一张（宁可贵一张图也不能黑屏）。低端机本来只走缩略图，不受影响。
- diag：新增 `bg-pool{total,kept,tier,limit,ratio}`、`bg-orig-aspect-skip`；`bg-preload`/`bg-apply` 增加 `crop`。
- 调试钩子：`window.elainaBgInfo()`（档位/比例/候选池/当前图裁切）、`window.elainaNextBg(reason)`。

### index.html / style.css / diag.js
- 设置面板新增「壁纸比例过滤」下拉：标准（≤20%）/ 宽松（≤35%）/ 关闭。
- `#glass-mode-select` 样式扩成 `#glass-mode-select, #bg-aspect-select` 复用。
- 诊断条 `bg=` 后面加 `cNN%`（`diag.js bgLabel()`）。
- 版本号：`style.css` / `diag.js` / `script.js` 统一 `?v=20261118`。

## 验证（本机）
- `node --check script.js`、`node --check diag.js` 通过。
- 无头 Chrome 在本机沙箱下用不了：多进程 IPC 被拒（`platform_channel 拒绝访问`），
  `--single-process` 能起但打开真实页面后 `Runtime.evaluate` 一律超时（data: 页正常）。
  改用 **vm 里跑真 `script.js`** 的单元验收 `.dsh/tools/bg_aspect_unit.js`：16/16 通过。
- 模拟清单（40×16:9 / 30×1.6 / 10×1.4 / 20×2.13 / 3×方图，共 103）：
  1520×720 标准档 kept=60、tier=0、limit=0.2、方图 0 入选；宽松 100；关闭 103；
  3840×1080 自动降到 limit=0.5、kept=60；1024×1024 方屏方图反而留池（kept=13）；
  500 次抽样全部在池内、0 次方图、覆盖 60 张；单图清单和脏数据（w/h=0）都不炸。
- 真实清单核对：elaina 图库 103 张里 61 张 640×360、3 张 640×640，
  19:9 屏标准档应保留 65 张（63%）。

## 遗留
- 手机端验收：`?diag=1` 看诊断条 `bg=thumb 640x360 c16%`，连看几轮确认 `c%` 不超阈值、不再出方图；
  设置面板切「宽松 / 关闭」各试一次。
- 比例按 `screen` 判定（不是视口）：没全屏、地址栏占位时也不会误杀 16:9；想改成视口口径只动
  `deviceAspectRatio()` 一处。
- 上游图库仓库（renleihaokun/Elaina-random-img）没动：随机接口无参数，改它也只影响以后的图。
